## Re-sync risks

- `conventions.md` documents the `next-intl` namespace mapping (`Host.*`/`Guest.*`/`Runs.*` per component) and the base token list (`--paper`, `--ink`, `--teal`, etc.) by reading `messages/en.json` and the compiled `_ds_bundle.css` at sync time. If a component's translation namespace changes, a new namespace is added, or a token is renamed/removed in `src/app/globals.css`, the header will describe a stale API — re-validate it against a fresh build before trusting it, per the base skill's "Author the conventions header" step (it re-checks automatically on every resync, but flags drift rather than silently fixing it).
- `componentSrcMap` is exhaustive here (11 components, all app-internal `src/components/**` files) rather than sparse overrides — this repo is an app, not a published package, so there's no `.d.ts`-driven auto-discovery to fall back on. Adding a new component to the design system means adding it to `componentSrcMap` by hand; it won't be picked up automatically.
- The Claude Design project also holds hand-authored content this sync never touches: `handoff/`, `moodboard/`, `qa/`, `templates/`, `uploads/`. These are out of the converter's write/delete globs by construction — safe as long as future syncs keep using the standard `writes`/`deletes` scoping from the base skill's §5, never a broader glob.
