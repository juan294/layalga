# Can an invited guest book two weeks from their preferred agent?

Research date: 2026-11-21. Repository: `juan294/layalga`. Product baseline: `develop` at `8fcc19fc77cad48348efd1e56aac625d67837db0`, package v2.4.0. Worktree: `/Users/juan/code/layalga`. Scope: existing guest and host behavior, browser WebMCP, and the documented ChatGPT and remote MCP channels. Platform sources below were retrieved on the research date.

**The booking engine already answers the two-week question for an invited guest.** Given a household invitation, party details and a date window, it finds feasible 14-night stays and recommends rooms available for the whole stay. Dates come back in arrival order. The recommendation describes which rooms fit each stay. The source of availability is the household ledger. (`src/core/booking/guest-action-input.ts:16`, `src/core/booking/guest-actions.ts:84`, `src/core/rooms/search.ts:80`, `src/core/rooms/recommendation.ts:22`)

**The missing part is access from a conversation with no L’Ayalga page open.** The current browser tools can fill a search, read results already on the page and prepare a booking for review. The underlying web actions run the search and submit the request. The checkout contains no remote MCP booking server or ChatGPT plugin package. The project roadmap explicitly defers remote OAuth-protected MCP. OpenAI documents this kind of remote connection for conversational access, with an optional in-chat interface. (`src/components/webmcp/guest-tools.ts:54`, `src/components/webmcp/guest-tools.ts:78`, `src/components/webmcp/guest-tools.ts:112`, `src/app/[locale]/g/[token]/actions.ts:40`, `docs/roadmap.md:36`) [OpenAI plugin MCP server guide](https://developers.openai.com/plugins/concepts/mcp-server)

## What the host and internal agent can already do

The host signs in with a household-mapped identity. Invitation capture explicitly distinguishes a new party from a selected returning party, including families with the same surname. The creator can retrieve the active link from capture history. Host decisions resume a particular interrupted request. The host also has room, policy, calendar and reminder controls. Of these, browser WebMCP covers three room-ledger operations: `layalga.host.read_rooms`, `layalga.host.prepare_private_block` and `layalga.host.prepare_room_control`. The page supplies up to 20 manageable rooms. Both preparation tools fill a visible form for a host to review and submit. (`src/lib/auth/current-host.ts:29`, `src/app/[locale]/(host)/actions.ts:47`, `src/app/[locale]/(host)/actions.ts:141`, `docs/guides/host-manual.md:37`, `docs/guides/host-manual.md:65`, `src/components/host/room-ledger.tsx:37`, `src/components/webmcp/host-tools.ts:50`, `src/components/webmcp/host-tools.ts:73`, `src/components/webmcp/host-tools.ts:102`)

The internal Strands agent already coordinates bookings. The web application dispatches typed runs to AgentCore, while PostgreSQL owns holds, occupancy and confirmation. The HTTP task route requires a service credential and accepts the application's task schema. Run status separately checks the requesting host's home or the guest's matching invitation. A run ID on its own grants no access. Neither the internal task route nor the read-only calendar feed implements MCP tool discovery for an external user. Public `llms.txt` links to manuals and architecture. (`src/app/api/agent/run/route.ts:11`, `src/agent/client.ts:51`, `src/agent/runtime/request.ts:23`, `src/app/api/runs/run-data.ts:99`, `docs/architecture/README.md:30`, `docs/architecture/README.md:45`, `public/llms.txt:5`)

The site also distinguishes information that each participant may see. A guest gets guest-facing room facts and an indication that another stay overlaps. Host notes and other guests’ identities stay outside that search result. Verified reminder contact and delivery state belong to the web application. The project documents that raw invitation and change-request prose can contain personal information and reach its model, even when structured fields have been removed. A ChatGPT or other agent conversation would introduce a further recipient for whatever the user types or its tools return. That last point is an inference about the proposed channel. (`src/core/booking/guest-actions.ts:151`, `docs/security/data-lifecycle.md:3`, `docs/security/data-lifecycle.md:54`, `docs/guides/host-manual.md:85`)

**Connecting privately and launching publicly are separate milestones.** OpenAI documents custom MCP connections for testing, subject to account or workspace permissions. Public distribution of a remote plugin requires a verified publisher, a plugin package, a stable HTTPS endpoint, domain verification, review and a subsequent publication action. For authenticated submissions, reviewers need a dedicated account with sample data, five positive cases, three negative cases and a video walkthrough. The listing requires a privacy policy. Approval or discovery of L’Ayalga from a generic booking prompt cannot be inferred from these requirements. Its intended audience today is the invited household and its guests.
