# Plan: show which Google account is signed in, and always offer the account picker

Date: 2026-10-17
Status: phases 1 and 2 implemented locally on 2026-10-17 ([notes](2026-10-17-host-sign-in-identity-notes.md)); phase 3 (release v2.3.0) awaits owner authorization
Research: none. Evidence below comes from the reads listed under "Verified baseline".
Base: `develop` at `66b3980` (clean tree; `main` is `78ddbbc`, v2.2.1)

## Why this plan exists

The owner signed in as host and could not tell which Google account was used. Three gaps:

1. Google's account picker did not appear. The Google call passes no `prompt` option (`src/app/[locale]/sign-in/sign-in-button.tsx:36-41`), so Google reuses the single signed-in session silently.
2. The header shows no identity. It holds the language selector, the theme toggle and Sign out (`src/app/[locale]/layout.tsx:96-116`). The hero greets the host by the name stored in `hosts.display_name` (`src/app/[locale]/(host)/page.tsx:227`), which does not prove which Google account signed in.
3. The host dashboard is titled "Guest stays" (`messages/en.json:64`), so the owner took it for the guest view. The page is the host dashboard.

## Verified baseline (read in this session)

- Host page: hero title from `t("title")` in `Host` (`src/app/[locale]/(host)/page.tsx:224-227`); five sub-pages show `t("nav.backToToday")` (`activity`, `settings`, `calendar`, `guests`, `rooms` pages, line numbers in the consumer sweep).
- Layout: `getCurrentHost()` and `getCurrentGuestInvitation()` in one `Promise.all`; `signedIn = Boolean(host || guest)` gates only the Sign out form (`layout.tsx:80-84`, `106-114`).
- `/visits` renders its own Sign out form in the page (`visits/page.tsx:113`), so a Google guest sees no layout Sign out today.
- Callback signs out an unrecognized account and redirects to `sign-in?error=not_a_host`; a missing code redirects to `oauth_failed` (`src/app/auth/callback/route.ts:48-60`). Both messages exist and are tested (`sign-in/page.test.tsx:62,70`).
- Local sign-in for tests: `signInAsHost` signs a fixture host up with `<uuid>@fixture.test` and email confirmation off (`src/test-support/host-session.ts:41-48`, `supabase/config.toml:229`). `household.signIn` returns nothing today (`tests/e2e/helpers/household.ts:20,49-50`).
- Vitest runs in the `node` environment; component tests use `renderToStaticMarkup` (`src/components/host/capture-invitation-form.test.tsx:1`).
- `UserIdentity.identity_data` is typed as an open object (`@supabase/auth-js@2.117.3` `types.d.ts:338-349`).

**INFERRED, not verified here:** that Google's identity data carries `picture` for production accounts. The fallback monogram makes a miss harmless, and phase 3 includes an owner check on production.

## Design options considered

| Option                                                             | Trade-off                                                                            | Verdict                                        |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Avatar from `user_metadata.avatar_url`                             | Simplest, but a user can set it to any URL through the client SDK                    | Rejected                                       |
| Avatar from `identity_data.picture`, validated, with CSP allowlist | One extra CSP host family; needs validation code                                     | **Chosen**                                     |
| No avatar, monogram only                                           | No CSP change, no third-party request                                                | Fallback only; the owner asked for the picture |
| Proxy the avatar through an app route                              | No CSP change, hides the viewer from Google, adds a route, caching and abuse surface | Rejected as disproportionate                   |
| Chip in host hero only                                             | Smaller diff, leaves Google guests with no identity                                  | Rejected                                       |
| Chip in the shared header                                          | One place for every signed-in surface                                                | **Chosen**                                     |
| Per-call `getUser()` in the layout                                 | No refactor, one more Auth round trip per page                                       | Rejected                                       |
| React `cache()` around the one `getUser()`                         | Removes the duplicate that exists today                                              | **Chosen**                                     |

- Press "Continue with Google": the Google account picker appears even with one signed-in account.
- After sign-in the header shows the chosen account's email and avatar (or monogram) next to Sign out, on desktop and phone.
- The dashboard reads "Household ledger" under "Host dashboard".
